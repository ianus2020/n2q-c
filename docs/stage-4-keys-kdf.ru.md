# Этап 4 — KDF, ключи и ограничение ресурсов

## Что исправлено

Прежний N2Q-PW склеивал пароль и соль без длин. При s_cost=1 разные пары
(password="a",salt="b"*17) и (password="ab",salt="b"*16) давали один ключ.
Параметры позволяли нулевые проходы, panic и неограниченные выделения памяти.
Эта реализация удалена из публичного API.

Новый pw::derive использует RustCrypto Argon2id v19 (argon2 0.6.0), а не новый
самодельный вариант Balloon. Возвращается Result<SecretKey256,KdfError>.
Соль 16–64 байта, пароль 1 байт – 1 МиБ. По умолчанию 64 МиБ / 3 прохода /
1 полоса. Допустимы 19–64 МиБ, 2–6 проходов, 1–4 полосы с общим максимумом
196608 КиБ-проходов. Лимиты проверяются до выделения и вычисления.
Память выделяется через try_reserve_exact, блоки и временный выход обёрнуты
в Zeroizing; используется hash_password_into_with_memory. Ограничение одного
вызова не заменяет очередь и лимит параллельных запросов сервиса.

SecretKey128/256 скрывают Debug, не реализуют Copy/Clone/Serialize, генерируются
через getrandom и стирают собственные байты при Drop. В WASM генерация и
успешно разобранные ключи используют эти типы. JS-строки, память браузера,
swap, дампы, копии у вызывающей стороны и временные копии компилятора полностью
не контролируются. Основание и ограничения: https://docs.rs/zeroize/1.9.1/zeroize/.

Rust absorb теперь использует один блок padding вместо копии всего ввода.
Буферы SIV-входа и потока ключа стираются; при ошибке SIV/stream проверки
тегa предварительный plaintext стирается. Не заявляется полное стирание
всех регистров и промежуточных состояний перестановки.

Python FireLine peer(name,integer_seed) удалён: он давал всего 256 вариантов
ключа. peer(name,trunk_bytes) импортирует ключ, new_peer использует os.urandom.
Детерминированный helper оставлен только как _demo_peer для старого тестового
вектора. Fresh API C/Python создаёт DEK и nonce через CSPRNG, выбирает Secure.
C стирает временный DEK. Python immutable bytes не дают гарантии стирания.
Оба порта ограничивают payload 16 МиБ, AAD 1 МиБ до шифрования/расшифрования.

## Совместимость и миграция

- SIV, nqc., N2QF v2 и действительные FireLine parcel в пределах лимитов
  сохраняют wire-формат. KAT и межъязыковые проверки обязательны.
- Ключи старого custom N2Q-PW **не совместимы** с Argon2id. Старые параметры
  s_cost/t_cost нельзя переименовать в memory_kib/passes.
- До обновления сохранить резервную копию шифртекстов и метаданные старого
  алгоритма. В доверенной изолированной среде старой версией вывести старый
  ключ, проверить и расшифровать данные; создать новую случайную соль,
  вывести новый ключ Argon2id, перешифровать, проверить повторное открытие
  и только затем атомарно заменить данные и метаданные. При ошибке сохранить
  оригинал. Пароли и ключи не помещать в логи/CLI arguments.
- Никакого автоматического угадывания версии или fallback на v1. Для данных
  без метаданных сначала определить старую конфигурацию и проверить копию.
  Массовая миграция реальных данных этой задачей не выполнялась.
- Минимальные параметры допустимого API — ограничение реализации, не
  универсальная рекомендация стойкости. Для новых данных использовать default
  и измерять нагрузку в реальном сервисе.

## Проверки

Регрессии включают RFC 9106 §5.3 Argon2id vector, прежнюю неоднозначную пару,
детерминизм, изменение стоимости, неверные/огромные параметры и длины,
редактирование Debug, fresh FireLine Secure, отказ RNG и лимиты C/Python.
Cargo.lock обновлены для native/WASM/fuzz/bench/cryptanalysis; CI использует
--locked, sanitizer C, существующие KAT и шесть файловых портов.
Локально доступны проверки в памяти и синтаксиса; выполнение Rust и полная
регрессия требуют CI. Независимая экспертиза N2Q остаётся отдельным условием.

Источники: https://www.rfc-editor.org/rfc/rfc9106.html,
https://docs.rs/argon2/0.6.0/argon2/,
https://github.com/RustCrypto/password-hashes/tree/argon2-v0.6.0/argon2.
