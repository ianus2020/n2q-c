# Этап 26 — результаты интерфейса после замены ключа

Подтверждён дефект фронтенда: ручное редактирование ключа удаляло старый
расшифрованный текст и результат blind index, а успешная кнопка «Новый ключ»
оставляла их на экране. Интерфейс показывал результаты предыдущего ключа рядом
с новым ключом. Браузерный regression test на прежнем app.js получил старый
текст `key replacement fixture` вместо пустого результата.

После успешного создания нового ключа интерфейс явно очищает оба отображаемых
результата. Тест также проверяет очистку ciphertext/nonce и запрет копирования
предыдущего результата. Это очистка DOM; гарантированное стирание памяти
JavaScript/WASM этой правкой не заявляется.

## Проверки

- Старый app.js: новый browser regression FAIL с ожидаемой причиной.
- Исправленный app.js: полный существующий browser suite PASS по loopback HTTP.
- Новая версия опубликована только на согласованном локальном тестовом HTTPS
  стенде; полный browser suite PASS. Проверены manifest hashes JS/WASM и release ID.
- Успешны существующие сценарии обоих размеров/профилей, UTF-8, очистки формы,
  CSP/headers, некорректного комплекта JS/WASM и отказов worker.
- Свежий dependency audit: 5 Cargo.lock — 0 advisories, npm — 0 vulnerabilities,
  Gitleaks — 0 findings в 58 существовавших перед этим этапом коммитах.
  RustSec database commit: `999ec89d5d3f10f20be14750ec8c2d8b44e0ac9b`.
- Первый локальный dependency run не был успешным: отсутствовал cargo-audit.
  После установки закреплённой CI версии 0.22.2 весь скрипт повторён с exit 0
  в новом каталоге результатов; неполные JSON не использовались как подтверждение.

Первый browser attempt также не засчитан: HTTP test host ещё не отвечал и
навигация завершилась timeout. Воспроизведение дефекта выполнено повторно после
подтверждённой готовности сервера, затем получены успешные HTTP и HTTPS результаты.

[Evidence](audit/2026-10-20-frontend-key-state/) содержит before/after logs,
dependency reports, хэши app.js/tests/build и SHA256SUMS. Тестовые строки
синтетические. Работа выполнена в ограниченном режиме обычного исправления
подтверждённой ошибки и регрессионной проверки.
