# Этап 30 — проверка полноты отчётов зависимостей

В `scripts/audit-summary.py` подтверждён ложный успешный результат: отсутствие
отчётов или повреждённый JSON не давали ненулевой код завершения. Скрипт также
мог вывести найденные проблемы и завершиться с кодом 0. Основной shell driver
уже учитывал ошибки самих инструментов, поэтому это не означает, что прежние
проверки реальных зависимостей были неуспешны. Пробел касался независимой
проверки содержимого отчётов.

Контроль полного driver на синтетических данных подтвердил границу дефекта:
если инструменты завершаются с кодом 0, но отдают повреждённый отчёт, прежний
driver принимал такой результат. Исправленный обработчик делает этот случай
ошибкой всего аудита.

Теперь обязательны пять Cargo-отчётов, npm и Gitleaks. Проверяются типы,
обязательные поля, согласованность Cargo `found/count/list`, npm totals и
наличие findings. Повторяющиеся JSON-поля, NaN, неверный UTF-8, ошибки npm/Cargo
и неподдерживаемый npm report version отклоняются. Находки дают ненулевой exit;
проверка остальных обязательных файлов продолжается после первой ошибки.
В лог не выводятся поля Gitleaks `Secret` и `Match`. Информационные Cargo warnings
по-прежнему отображаются без самостоятельного изменения политики аудита.

## Проверки

- На прежнем обработчике текущие девять тестов не прошли: 26 отказов проверок
  внутри subtests. Это случаи проверки отчётности, а не 26 уязвимостей проекта.
- Девять тестов исправленного обработчика PASS на Python 3.14.8 и 3.9.6,
  включая полный shell driver с подставными инструментами, которые всегда
  завершаются с exit 0. Корректные отчёты принимаются, повреждённые отклоняются.
- Все 60 Python-регрессий PASS. В журнале сохранены прежние предупреждения
  очистки ресурсов SQLite/HTTPError; они не скрывались и не считаются новыми
  успешными проверками корректного освобождения ресурсов.
- Свежий полный dependency audit PASS: пять Cargo.lock — 0 известных
  уязвимостей, npm — 0, Gitleaks — 0 находок в 62 существовавших перед этапом
  коммитах. RustSec database commit:
  `999ec89d5d3f10f20be14750ec8c2d8b44e0ac9b`.
- CI verification manifests теперь включают хэши обработчика и его тестов.

[Evidence](audit/2026-10-20-dependency-report-validation/) содержит контроль
прежнего кода, логи проверок, JSON инструментов, хэши исходных файлов и SHA256SUMS.
Результат не является независимой криптографической экспертизой; неизвестные
уязвимости зависимостей этим аудитом не исключаются.
