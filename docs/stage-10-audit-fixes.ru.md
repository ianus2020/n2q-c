# Этап 10 — исправления по дополнительному криптоанализу

## A-01: неоднозначная граница convergent master key / content

До исправления C/Rust/Python/Go принимали master key переменной длины и вычисляли
`H(master_key || content)[:16]`. На исходнике этапа 9 воспроизведено:
`(b'A'*16, b'Bpayload')` и `(b'A'*16+b'B', b'payload')` дают одинаковый DEK.
DEK второй пары открывает шифротекст первой. Это совпадение кодирования,
а не найденная коллизия QP/хэша. Для эксплуатации нужны связанные/контролируемые
ключи разной длины; восстановления произвольного неизвестного master key нет.

Все четыре порта теперь требуют ровно 16 байт master key. Формат корректных
16-байтовых входов, DEK и ciphertext не изменились. Python выдаёт ValueError,
Go — nil/nil; Rust требует `&[u8;16]` на уровне типов (изменение исходного API).
Данные с историческими ключами иной длины требуют отдельного offline-решения;
не реализован неявный fallback или автоматическая миграция.

В C также обнаружены unchecked `malloc(mklen+len)`, арифметика размеров и отсутствие
outcap. Теперь есть лимит content 16 МиБ, проверка размера/указателей/профиля,
ошибки malloc, outcap для seal/open и сброс outlen. Это изменение C API:
`n2q_conv_seal(..., out, outcap, fast)` и
`n2q_conv_open(..., out, outcap, outlen, fast)`. Все внутренние вызовы обновлены.
Временные буферы C/Rust и доступные копии Go очищаются; полное стирание всех
копий/памяти ОС этим не гарантируется.

## A-02: сравнение key commitment

В Rust/Python/Go использовалось обычное равенство массивов/bytes. Заменено на
полный XOR-проход Rust, hmac.compare_digest Python и crypto/subtle Go.
Это исправление риска раннего выхода в сравнении. Временная эксплуатация
данного API не доказана, и весь Python/Go/Rust runtime constant-time не объявлен.
Регрессии меняют каждый из 256 бит commitment.

## A-03: завышенные выводы старого инструмента

Убраны формулировки «PROVEN empirically», утверждение zero-sum iff low degree,
вывод о вероятности ниже разрешения выборки и вывод о минимуме из тайм-аута.
Новые отчёты отделяют измерение, точный перебор и SAT. Общие теоремы sponge/SIV
не являются доказательством безопасности конкретной композиции N2Q.
