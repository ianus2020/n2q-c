# Этап 17 — общий дедлайн локального TLS-запроса

## Воспроизведённая проблема

Прежний socket timeout 3 с ограничивал ожидание очередных байтов. Клиент мог
посылать часть HTTP-заголовка каждые 0.5 с, держать worker дольше тайм-аута и
успешно закончить запрос: в опыте ответ 204 получен через 4.579 с.
При занятых 16 workers это позволяло удерживать весь доступный пул.
Речь о loopback reference stand; внешнее production-развёртывание не выполнялось.

## Исправление

Каждому принятому соединению задан общий дедлайн 3 с на TLS handshake,
заголовки, тело и ответ. Watchdog вызывает shutdown TCP-соединения через
дубликат дескриптора: передача владения в SSLSocket не позволяет потерять
доступ к соединению. После запроса timer отменяется/завершается, дубликат
закрывается, slot возвращается. Сохранены idle timeout и предел 16 workers.

Завершение соединения не откатывает уже выполненный COMMIT. Подписант обязан
сжечь индекс при отсутствии однозначного подтверждения; соответствующий
mTLS/C тест потери ответа после COMMIT проходит и после изменения.

## Проверки

- Регрессия slow headers + saturation + восстановление worker: на прежнем
  обработчике из `7988f1e` ожидаемый FAIL (204 вместо закрытия); новая версия PASS.
- Неполный TLS handshake закрывается, последующий проверенный запрос проходит.
- Все 3 TLS-теста PASS на системном Python 3.9/LibreSSL и на Homebrew Python
  3.14.8/OpenSSL 4.0.3; во втором случае PKI создана LibreSSL 3.3.6.
- Полный набор Python: 41 тест PASS (29.000 с), включая реальный C mTLS callback,
  CoNe restart/concurrency/snapshot/network failure, publication и migration CLI.
- Новый отдельный синтетический стенд: HTTPS + mTLS C signer check PASS;
  полные Chromium-сценарии HTTPS PASS. После проверки оба процесса остановлены.
  Рабочая `.local-stand` и её счётчики не сбрасывались.
- Полный native после этапа 16 PASS: 39 Python, C sanitizers/TSan, Rust,
  WASM bindings, Go race, PHP/Swift и interop между шестью портами.

Логи и хэши: [evidence](audit/2026-10-19-tls-deadlines/).

GitHub повтор `7988f1e` по-прежнему выявляет issuer validation на macOS;
отказ сохраняется открытым до фактического исправления и успешной проверки.
Это не подтверждение production DoS-устойчивости, независимого внешнего
криптоаудита или стойкости 128/256 бит.
