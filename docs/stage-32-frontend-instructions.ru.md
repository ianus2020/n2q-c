# Этап 32 — инструкции фронтенда и примеры WASM

Проверен версионируемый браузерный стенд `impl/n2q-c-wasm/web` и связанные
разделы README/JavaScript в английском и русском руководствах. Сверка выполнена
с текущими WASM bindings, worker, `modes.rs` и `frame.rs`.

## Исправления

- В `impl/README.md` оставалась команда обычного `http.server`, которая не
  выставляет проверяемые response headers. Теперь раздел ссылается на общую
  инструкцию сборки/запуска через `scripts/serve-web.py`.
- Инструкция сборки явно использует Rust 1.96.1, wasm32 target и wasm-pack
  0.13.1, как текущий CI, с `--locked` и `RUSTUP_TOOLCHAIN` для сборки.
- На странице добавлен воспроизводимый пример: новый ключ, AAD `demo:v1`,
  текст `Привет 🌍`, перенос токена вместе с AAD и дешифрование.
- Подсказки уточняют длины ключей/nonce/результатов, байтовые лимиты UTF-8,
  сохранение AAD отдельно, автоматический выбор схемы при дешифровании,
  текстовые SIV-токены и отдельные инструменты для файлов/паролей.
- Вместо коротких JS-фрагментов с неопределёнными `keyHex`/`nonceHex` оба
  руководства ссылаются на один полный пример: import, await инициализации,
  генерация ключа/nonce, `seal128(false, ...)` и `open128(...)`.

## Сверенные параметры

| Возможность | Поведение текущего кода |
|---|---|
| Размер/профиль по умолчанию | N2Q-128, Secure; Secure = 16, Fast = 8 раундов |
| Ключ | 32 hex для N2Q-128, 64 для N2Q-256; готовый ключ, не пароль |
| Nonce | 16 байт / 32 hex для обоих размеров; включён в токен |
| Токен | `nqc.` + canonical base64url, wire-frame version 1, SIV; ключ/AAD не входят в кадр |
| Дешифрование | Размер/профиль/nonce берутся из токена; требуются исходный ключ и AAD |
| Хэш | 64/128 hex для N2Q-128/256; ключ не используется |
| Blind index | 32/64 hex; использует ключ, размер и профиль, детерминирован |
| Лимиты | Текст/hash/index: 1 МиБ UTF-8; AAD: 256 КиБ; токен: 2 МиБ |

Кнопки и сценарии сопоставлены с фактическими `app.js`/worker handlers.
Смена размера сохраняет ключ; создание нового ключа очищает старые отображаемые
результаты, перенос токена очищает прежний расшифрованный текст, очистка формы
завершает worker. Исходные app/worker/Rust API на этом этапе не менялись.

## Проверки

- Свежая locked-сборка JS/WASM из текущего кода PASS. Журнал включает сообщения
  wasm-pack о fallback установки wasm-bindgen, optional metadata и наличии
  более новой версии; проверялась закреплённая версия 0.13.1.
- Полный JS-пример извлечён непосредственно из README и выполнен в браузере
  по HTTP и временному HTTPS. Дополнительный same-origin module route
  используется только инструментом проверки, с exports для наблюдения;
  публичный release и CSP ради примера не изменялись.
- Пошаговый UI-сценарий и все четыре сочетания размера/профиля PASS по обоим
  протоколам: UTF-8 roundtrip, перенос AAD, отказ при неверном AAD,
  автоопределение после изменения selectors, длины хэша/индекса и детерминизм.
- Проверен хэш с пустым ключом, очистка формы, отсутствие page errors и
  горизонтального переполнения при ширине 1100 и 390 px.
- Полный существующий browser regression suite PASS по HTTP и HTTPS, включая
  неверный комплект JS/WASM, ограничения UTF-8, отказы и дедлайны worker.
- Проверка до изменений подтвердила очистку ключа при перезагрузке Chromium;
  она не выявила runtime-дефекта. Новый текст предлагает явную очистку формы
  и сохранение ключа/AAD, без гарантии стирания памяти браузера.

[Evidence](audit/2026-10-20-frontend-instructions/) содержит скрипт проверки,
исходные наблюдения, результаты примеров и browser suite, build manifest,
журналы сборки, хэши исходных файлов и SHA256SUMS. Проверка относится к текущим
исходникам фронтенда. Опубликованная внешняя версия не проверялась и не
обновлялась; сохранённый `.local-stand` не менялся. Серверы и PKI проверки
были временными, данные синтетическими. Криптографическая стойкость этой
сверкой документации не устанавливается.
