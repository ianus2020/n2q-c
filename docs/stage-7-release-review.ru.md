# Этап 7 — финальная проверка реализации и передача на независимый аудит

## Дополнительное исправление C

Встраивание n2qc.c с N2Q_CORE_NO_MAIN позволяло вызвать криптооперации без
init_anf(). Тогда массивы anf_cnt/anf_mono оставались нулевыми, S-box выдавал
нули и криптографические свойства нарушались. Штатные CLI/self-tests вызывали
инициализацию; риск относится к интеграциям, пропустившим её. Не установлено,
использовались ли такие интеграции с реальными данными.

ANF теперь константный, механически выведенный из SBOX. init_anf оставлен
совместимым no-op. Ручная инициализация больше не нужна и не пишет глобальное
состояние. tests/core_init.c независимо пересчитывает коэффициенты, сверяет KAT
до первого вызова init_anf и проверяет параллельные hash/init под ASan/UBSan/TSan.
Алгоритм и действительные результаты инициализированного ядра не меняются.
Если сторонняя интеграция применяла старое ядро без init_anf, её данные нужно
отдельно проверить; обычная замена библиотеки не восстанавливает прошлую защиту.

## Воспроизводимые входы проверок

Существующие native/web/fuzz задания дополнены verification record:
SHA checkout, публичные версии инструментов, SHA-256 lockfiles/векторов/workflow,
результат предшествующих шагов и public JS/WASM manifest. Записи хранятся в
GitHub Actions artifacts verification-native/web/fuzz/dependencies 14 дней. Переменные среды,
ключи, plaintext и credentials не выгружаются. Статус failure не превращается
в success из-за наличия файла отчёта.

Проверка зависимостей запускает cargo-audit 0.22.2 (--locked при установке)
по всем пяти Cargo.lock и npm audit с audit-level=low. Gitleaks 8.30.1 проверяет всю полученную git-историю
(--all, fetch-depth=0); вывод и JSON редактируются --redact=100, содержимое
секретов не печатается. Источник: https://github.com/gitleaks/gitleaks/releases/tag/v8.30.1. Уязвимости не
игнорируются по ID; все JSON-отчёты сохраняются, в том числе при отказе.
Актуальная RustSec DB меняется со временем; её revision присутствует в отчёте.
Отсутствие известных advisory не доказывает отсутствие уязвимостей.
Источник инструмента: https://github.com/rustsec/rustsec/tree/cargo-audit/v0.22.2.

Сборки используют Cargo --locked, npm ci, Rust 1.96.1, wasm-pack 0.13.1,
cargo-fuzz 0.13.2, nightly-2026-10-18 и actions с commit SHA. macOS runner,
Homebrew PHP, Node 22 и Go 1.26 получают обновления; artifact записывает
реально использованные версии. Не заявлена побитная воспроизводимость бинарей
между разными runner/SDK/компиляторами. Для выпуска потребуется отдельно
зафиксировать образ, SDK и все toolchain patches и сравнить независимые сборки.

Команды (в отдельном checkout с зависимостями):
- scripts/dependency-audit.sh — RustSec и npm, после установки cargo-audit 0.22.2
  и npm ci --ignore-scripts.
- scripts/check.sh — native/KAT/sanitizers/IO/межъязыковая матрица.
- scripts/fuzz-smoke.sh — пять целей, по 2000 прогонов, до 20 секунд на цель;
  N2Q_FUZZ_RUNS/N2Q_FUZZ_SECONDS позволяют увеличить бюджет в доверенной среде.
- scripts/build-web.sh — locked WASM/glue и manifest.
- python3 scripts/serve-web.py --port 8765 — loopback test host;
  npm ci, установка Chromium через Playwright, затем npm run test:web.
- python3 scripts/verification-record.py --job native --output evidence.json
  записывает публичный состав сборки; это не самостоятельный запуск тестов.

## Что передать внешним рецензентам

Исходники и историю PR, SPEC/APPENDIX-A, impl/conformance/vectors.txt,
описание N2QF v2 и доменов, все тесты и seed generator, CI run и artifacts.
Рецензентам отдельно проверить перестановку QP и выбор констант, SIV proof
и domain separation, Fast-профиль, границы forgery/security level, side channels
на целевой платформе, FireLine wrapping/recipient binding, упрощённые CoNe
цепочки и доверенный монотонный якорь. Собственные KAT/фаззинг не заменяют
независимый криптоанализ и не доказывают уровни 128/256 бит.

## Условия, которые не закрывает этот PR

- Независимая криптографическая экспертиза N2Q и устранение её результатов.
- Реальный внешний монотонный backend CoNe с общей атомарной выдачей индексов,
  долговечностью, backup/restore политикой и проверкой на целевом хранилище.
  Нельзя подключать тестовый in-memory callback в эксплуатацию.
- Проверка фактического HTTPS-хостинга, CSP/headers/cache и атомарного размещения
  web-комплекта. Тестовый сервер не является production сервером.
- Инвентаризация старых N2QF v1/custom PW данных, резервные копии и миграция
  в доверенной среде. Никакие реальные пользовательские данные не мигрированы.
- Квоты диска/CPU/параллелизма/загрузок, lifecycle ключей в KMS, операции
  инцидентного восстановления и измерение side channels на реальных устройствах.

PR остаётся draft. Слияние, выпуск и deployment не выполняются автоматически.
