# Этап 12 — сохраняемый backend якоря CoNe и C mTLS-провайдер

По указанию пользователя подготовлен локальный backend, а не развёртывание
сервиса для реальных ключей. Контракт и ограничения — в tools/anchor/README.md.

Добавлены HTTPS/mTLS сервис, SQLite WAL/FULL с транзакционным сравнением индексов,
привязка сертификата клиента к конкретным key_id и libcurl callback для реального
`n2q_cone_sign_reserved`. Нет автоматического создания потерянной БД или API сброса.
Неизвестный исход сетевого запроса не выдаёт подпись и расходует индекс.
Сервис слушает только loopback, ограничивает workers/тайм-ауты/размер JSON.

Проверки на синтетических данных:

- C signer под ASan/UBSan: проверяемая подпись через настоящий mTLS callback;
- 16 конкурентных запросов через два процесса сервиса: один 204, остальные 409;
- SIGKILL обоих процессов и повторный запуск: использованные индексы отвергнуты;
- откат старой копии журнала подписанта отвергнут сервисом;
- недоступность/неверный CA/потерянный ответ после COMMIT: подпись не выдана,
  индекс локально израсходован, следующая корректная операция проходит;
- сертификат без разрешения, чужой key_id, отсутствующий сертификат и неверное
  имя сервера отвергнуты; дубликаты JSON/неверные индексы/лишний объём отвергнуты;
- потерянная БД не воссоздаётся; init существующей БД, public permissions,
  symlink/hardlink отклоняются.

Локальные результаты подтверждают код и модель отказов процесса/сети. Не
подтверждены отдельный от подписанта эксплуатационный домен хранения,
отсутствие отката всей машины/БД якоря, физическое отключение питания и backup
restore политика реальной инфраструктуры. Stateful CoNe и его криптографические
ограничения не изменились. Backend не хранит seed и не снимает лимит 16 подписей.

Первый CI этапа 12: Linux anchor PASS, macOS native остановился на startup
test TLS. Генерация test PKI теперь явно задаёт SKI/AKI вместо зависимости от
умолчаний конкретного OpenSSL CLI; strict X.509 включён на обеих сторонах.
Добавлены точная диагностика readiness и уборка процесса даже при ошибке setUp.
Локально все шесть тестов с strict validation PASS; повторный CI проверяет macOS.

В этапе 15 причина воспроизведена с исходным generator и LibreSSL CLI:
strict OpenSSL выдаёт Missing Authority Key Identifier. Новая версия с явными
SKI/AKI прошла все шесть тестов в этой же комбинации. Проверка не ослаблялась.
