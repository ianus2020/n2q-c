# Этап 27 — запуск локального HTTP test host

При обычной проверке фронтенда наблюдался timeout навигации до готовности
HTTP-сервера. Проверка кода показала зависимость запуска от reverse DNS:
стандартный HTTPServer.server_bind вызывает socket.getfqdn до начала listen.
Локальному хосту на 127.0.0.1 DNS-имя не требуется. Контроль с недоступным
getfqdn воспроизвёл отказ старого кода; реальная задержка системного DNS в
этом контроле не имитировалась ожиданием или сетевой нагрузкой.

`scripts/serve-web.py` теперь использует LocalHTTPServer: TCP bind выполняется
непосредственно, имя и порт берутся из привязанного числового адреса. Такой
подход уже используется в локальном HTTPS-стенде. Добавлен regression test,
который запрещает DNS lookup, запускает сервер и проверяет GET/HEAD, CSP,
nosniff, no-store и отсутствие тела в HEAD.

CI verification record дополнен хэшами этого теста, frontend assets и browser
suite, чтобы изменения интерфейса были явно видны в сохраняемых manifests.

## Проверки

- Старый startup с недоступным getfqdn: FAIL, один вызов DNS подтверждён.
- Новый startup и GET/HEAD/headers: PASS.
- Все 51 Python regression tests: PASS.
- Реальный запуск обновлённого CLI и полный browser suite: PASS.
- Однократный локальный замер готовности HTTP — 0,068 секунды.
- Временные HTTP test hosts остановлены после проверок.

[Evidence](audit/2026-10-20-http-startup/) содержит контроль старого поведения,
замер, полный лог 51 теста, browser log и source hashes/SHA256SUMS. Это исправление
обычной воспроизводимости test host; независимые испытания реальной инфраструктуры
этим не заявляются. В Python log есть ResourceWarning старого теста локального
HTTPS о cleanup объекта HTTPError; он не скрыт и не является падением тестов.
