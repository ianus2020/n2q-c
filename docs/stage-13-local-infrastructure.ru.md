# Этап 13 — локальный HTTPS-стенд и конфигурации

Пользователь явно выбрал подготовку локального стенда. Инструкции:
tools/local_stand/README.md. Стенд создаёт отдельные private каталоги web,
anchor, signer и test PKI, не устанавливает CA в системное доверие и слушает
только loopback. Реальные данные/ключи не используются.

Публикация выполняется в content-addressed release; index/worker/JS/WASM
получают один versioned URL prefix. Смена current pointer атомарна, старые
страницы продолжают читать свой release. Manifest/hash/size и allowlist
проверяются до публикации; ошибки не меняют прежний current. Квота — 16
releases/64 МиБ; никакой автоматической очистки активных версий.

Проверены TLS с явным CA, отказ при недоверенном CA/имени, заголовки защиты,
MIME WASM, запрет обхода путей/PKI, отказ при смешанной сборке/симлинках и
сохранение старой версии. Одноразовый запуск `--check` проверил реальную подпись
C через mTLS. Отдельный Chromium-прогон выполняется по HTTPS; игнорирование
доверия браузера допускается только явным флагом для test CA, при этом Python/C
проверяют сертификаты без обходов.

Linux systemd шаблоны ограничивают память/CPU/tasks/FD и доступ к файловой
системе; на macOS они не запускались и не объявлены подтверждёнными. Реальная
edge-инфраструктура, KMS, отдельное хранилище якоря, нагрузочные/физические
испытания и production-развёртывание остаются открытыми.
