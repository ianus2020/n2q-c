# Этап 28 — очистка результата при переносе нового токена

Подтверждён дефект интерфейса: после успешного дешифрования одного сообщения
кнопка «В поле дешифрования» переносила новый токен и его AAD, но оставляла
на экране текст предыдущего сообщения. Программная замена полей не вызывает
обработчики `input`, которые очищают результат при ручном редактировании.

Кнопка теперь явно очищает `out-pt`. Она по-прежнему переносит только последний
успешный результат шифрования и связанный с ним AAD. Это исправление отображения
состояния формы; нарушения проверки аутентичности токена и гарантированного
стирания памяти этой проверкой не устанавливаются.

## Проверки

- На прежнем `app.js` новый браузерный тест завершился FAIL: после переноса
  нового токена найден синтетический `key replacement fixture` вместо пустого
  результата.
- После исправления полный существующий browser suite прошёл по loopback HTTP
  и локальному HTTPS. Тест проверяет оба перенесённых поля, очистку старого
  результата и успешное дешифрование нового сообщения `copied token fixture`.
- Сохранились проверки обоих размеров/профилей, UTF-8, заголовков, комплекта
  JS/WASM, завершения worker, очистки формы и дедлайнов.
- HTTPS-проверка использовала временный каталог, тестовую CA и временный
  сервер; после проверки сервер остановлен, каталог удалён. Существующий
  `.local-stand` не менялся, реальные данные и инфраструктура не использовались.
- Повторный dependency audit завершился с exit 0: пять Cargo.lock — 0 известных
  уязвимостей по RustSec database commit
  `999ec89d5d3f10f20be14750ec8c2d8b44e0ac9b`, npm — 0, Gitleaks — 0 находок
  в 60 существовавших перед этапом коммитах. Новые неизвестные уязвимости
  такой проверкой не исключаются.

Дополнительное сканирование всего рабочего каталога через `gitleaks dir`
не засчитано как PASS: оно также захватило четыре игнорируемых тестовых
private keys из `.local-stand` и четыре существующих публичных вектора/хэша.
Эти локальные тестовые ключи в коммит не включались. Для новых изменений
используется отдельная проверка staged Git diff с действующими правилами
репозитория; правила и исключения не расширялись.

[Evidence](audit/2026-10-20-frontend-copy-state/) содержит журналы до/после,
полные JSON dependency reports, хэши исходных файлов и SHA256SUMS.
Результаты CI нового коммита проверяются отдельно после отправки в PR.
